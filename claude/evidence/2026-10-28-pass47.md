## 1. Core AI Qwen3 4B closes PodSkipper (export + source + lab)

- **What the exports show.** 27 Oct 23:53: Qwen3 4B downloaded again and chosen; prepared in 0:09; #691 started 23:53:49; at the next launch (23:55:06) the note says it closed at **part 3 of 6, 1,093 prompt tokens, writing classification · 1 token**, sequential engine, 5,301 MB allowed. The resumed job finished from part 3 in 86 s. No iOS report and no MetricKit diagnostic for it (export taken 31 min later); MetricKit's daily exit counts for 23 Oct (the earlier closure) show **no foreground exit of any kind**.
- **Ruled out.** Part size: Pass 46's 1,536 ceiling held and it closed at 1,093. Memory headroom: 5.3 GB allowed. The prompt read: the first token was chosen, so the prefill finished both times.
- **The pattern (every Core AI run in the export, partReads).** Core AI's sequential engine keeps its memory (KV cache) in a `GrowingNDArrayState` (coreai-models `StateHandler+NDArray.swift`): 256 → 512 → 1,024 → 2,048 tokens, a new array and a copy each time, under a model already bound to the old one.
  - Closed: 23 Oct part 2 = 1,694 tokens after a part 1 of ~820 (memory 1,024 → 2,048 after use); 27 Oct part 3 = 1,093 after two parts under 1,024 (same). Pass 45's #960 part 3 of 11 fits the same shape.
  - Finished: every retry (a fresh engine whose first part grew the memory once, before it was used: 1,694 and 1,093 read "0 kept from before"); every run whose first part was already over 1,024 (Tristan Bowling, 11 parts from 1,486; #691 on 22 Oct from 1,239; MiniCPM5 #691 from 1,266).
  - Mechanism inside Core AI's framework (closed source) not proven; the trigger is.
- **Fix (`CoreAIBundleLimits.heldMemory`, `CoreAIClassifierSession.makeEngine`).** The engine is made by `EngineFactory` with `kvCacheStrategy: .fixedSize` at the route's held length (sequential 2,048; pipelined 1,024), CoreAIRunner's configuration otherwise. The memory never grows while an episode is read — the shape every successful phone run had. Static-shape engines and the Mac lab (unless `COREAI_LAB_IOS_CAP=1`) unchanged; `COREAI_LAB_GROWING=1` restores the old memory for an A/B. Diagnostics' engine line now says "memory for 2,048 tokens made at load".
- **Lab (real Core AI Qwen3 4B build `~/Developer/pk-coreai/qwen3-4b/macos`, the phone's caps, #691 as the app reads it):** fixed memory and growing memory gave **identical cuts** (10 cuts, 430 tokens written, `build/p47/{fixed,growing}/app.cuts.json`). The Mac never closed with either; this is a parity check, not proof of the phone fix.
- **Pass 46's ceiling removed** (`ModelPromptPlan`: no `promptCeiling` for Qwen3 4B). It closed again under it, and the lab had measured its cost (fused heard 33.7 → 35.0, show 28.5 → 31.8 s/h). The checkpoint/resume and one-retry crash guard stay.

## 2. Playback resumes earlier after reopening (export + source + unit)

- **His trace, 22 Oct:** "pause requested" at **1,233.1 s** (20:52:21), two launches, then "play" at **443.3 s** two seconds after the 21:23:59 launch — 13 minutes back.
- **Mechanism (source).** `restoreLastSession` called `load()` and then compared the crash-safe snapshot with `duration`. Since Pass 41 `load()` opens the file off the main thread and returns before it is open, so `duration` was still 0, the snapshot was ignored, and the finished load started from the library record — which is written once a minute or on a pause, and is lost if iOS ends the app before SwiftData saves (paused from headphones or the Lock Screen, PodSkipper is in the background; the phone has 5–10 background memory-pressure exits a day). `finishLoading` then wrote that older position back over the snapshot.
- **Fix.** `Episode.playbackPositionChangedAt` (additive optional) dates every intentional position (`setPosition`): the player each minute and at a pause/seek/switch, finishing, mark played/unplayed, history import, iCloud. `PlaybackState` snapshots carry `savedAt`; for its episode the snapshot wins unless the record was set later (`fresherPosition`). It is adopted in `restoreEpisode` (also for streamed episodes not put in the player) and in every `finishLoading`. A pause and an episode switch save the library at once (`saveLibrary`, failure logged).
- **Unit:** `Pass47PlaybackRestoreTests` (snapshot vs older/undated/newer record, other episode ignored, streamed episode's record caught up, start position).
- **Migration (sim library, not disposable phone data):** the test host opened the simulator's own library (5,893 episodes, 30 shows, 216 cuts) with this build; the column was added in place and the data is there. No pre-Pass-47 copy of a real library was available to diff against.

## 5. Reader learning (export + source + lab)

- **Why every training since 22 Oct was rolled back.** His correction ledger still holds a **21-minute "ad" he added on Whiskey Ginger (Ryan Hamilton) 2,442–3,707 s and later removed** (no such cut in the episode now) and a superseded 30-s add. The learner made 535 "ad" sentences of the show from it at weight 5; with his other corrections ~80 % promos and weighed ~10× the lab sentences replayed, the head learned to call most things promos (phone: lab loss 0.088 → 0.381).
- **Reproduced (lab, the current readers' features for all 70 exported episodes, `reader_consensus.py` variant `gold46`):** lab loss 0.088 → **0.509**; through the app's detector on the 59 labelled episodes (two folds, each scored by heads trained without it): heard **61.5** s/h, show cut **84.7**, missed 89/418 (shipped reader 7.8 / 9.5 / 13 — in-sample: Pass 44 trained it on these labels).
- **Fixed data (`goldLabels(…current:)`, policy 47).** A correction teaches only while a current cut covers half of it (a Not an Ad: under a fifth), each sentence the kind of the cut over it now; the show far from every cut in a reviewed episode keeps the lab's promo share; one episode ≤ 150 gold sentences' weight; everything learned ≤ the replayed lab sentences; old examples rebuilt. `gold47`: lab loss 0.088 → 0.084 / 0.087 — but the detector heard **15.1** s/h (show 8.9, missed 28/418): the overall loss stayed in bounds while each reader traded one class for the other (`build/p47/headcheck.py`: reader 1 promo loss 0.126 → 0.093 with show 0.058 → 0.075; reader 2 the reverse).
- **Per-class check.** No epoch at learning rates 1e-3, 3e-4 or 1e-4, from his corrections alone or with model agreement, improved both readers without making the promos or the show worse. The learner now keeps a head only if the lab's promos and the lab's show each stay within 1 % (`withinLab`), takes the last such epoch, and otherwise rolls back saying so.
- **Conclusion (accurate, not a completion).** Head-only learning cannot measurably improve the Reader from the evidence on his phone (4 corrected episodes, 4 with independent model agreement); the on-device learner now refuses heads that would make it worse, and no longer learns from removed corrections. The measured lever remains whole-Reader retraining (Pass 44: heard 37.6 → 27.4 s/h held out) once more independent labels exist. **Not done this pass:** a new whole-Reader training run.
- **Unit:** `Pass47LearnerTests` (removed add teaches nothing; kinds from current cuts; balance and cap; Not an Ad in force; epoch keep), `Pass38LearnerTests` updated.

## 6. iCloud sync (source + unit; architecture decision)

- **Found.** Positions merged by when an episode was last *started* (`lastPlayedAt`), so a later pause on the other device lost to an earlier one and a rewind could never win; the episode loaded in the player was never updated; 600 episodes; pauses sent only when the app went to the background; follows additions-only — and an unfollowed show was added back by the other device's list.
- **What his signing allows (export).** The installed app carries the iCloud key-value entitlement (Resources: "iCloud key-value storage: Yes"); "iCloud: received 0" in every export — nothing has ever arrived from a second device. Feather re-signs with a randomized bundle id (`app.ivory2951.coral5096`); CloudKit needs an iCloud container in the provisioning profile, which this export can't show. **Decision:** keep iCloud key-value storage (works with his signing today) and make it correct; CloudKit or a Cloudflare service is the next step if two devices are confirmed and the 1 MB limit binds (cuts of un-reviewed episodes don't fit it).
- **Built.** `listening.v2`: per episode, position with its own change time, played/starred with theirs, last started; merged part by part, the newer winning (a newer rewind wins); ~1,500 most recently changed episodes in 200 KB; a pause sent one second after it happens; a paused episode in the player moves to the other device's newer position (a playing one doesn't); older builds' `episodes.v1` still read. Unfollows recorded (`unfollowed.v2`): not re-added; mirrored only where the show holds nothing of his (corrections, downloads, a started or saved episode), otherwise kept and listed in Settings. Settings shows the signed iCloud store identifier, which must match on both devices.
- **Unit:** `Pass47ListeningSyncTests`. **Not verified:** any two-device sync.

## 7. Downloads & Storage (source + unit)

- **Found.** Transcripts counted only when the record's flag said so; files no record named never appeared anywhere (the page listed records, not files); resumable-transcription and model-answer files were removed with a transcript but never counted.
- **Built.** `EpisodeFileInventory` scans the episode, transcript and checkpoint folders and matches files by name to every episode: transcripts count whatever the flag says (and those episodes are listed and removable); checkpoint bytes count with the transcript; "Files No Episode Uses" lists and removes the rest (never anything changed in the last 15 minutes, nothing outside those folders), reporting the bytes actually removed. Removal fetches episodes by id. **Unit:** `Pass47StorageInventoryTests`, Pass 45 storage tests.
