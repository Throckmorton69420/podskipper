Input: his "stop asking me such detailed specifics and start implementing it all in whatever order that's most logical to complete everything". Starting HEAD bc0503d. Levels: **source**, **unit**, **sim**, **device build**. **Nothing here is phone-verified.**

## 1. Order chosen

Reliability first (the deprecated interruption API the device build warned about), then the open transcript item, then cross-device sync, then the rest of X50-05/X47-09 (see §5).

## 2. What changed

| Area | Before | Now |
|---|---|---|
| Interruptions | `AVAudioSession.interruptionNotification` with began/ended type, option and reason keys — all deprecated in iOS 27.0, the deployment target | `didBecomeInactiveNotification` (only `DeactivationContext.source == .system`; reason from `interruptionContext.reason`) → `interruptionBegan(reasonRaw:)`; `resumptionRecommendationNotification` (`ResumptionContext.recommendation == .shouldResume`) → `interruptionEnded(shouldResume:)`. Same decisions as before: route-disconnect never ends, his "resume after interruption" setting still wins |
| Transcript | Stayed in a 340-point window above the full controls | While you scroll back or search, the 340 cap lifts and the controls become one glass row (`TranscriptReadingBar`: title, back 15, play/pause, forward 30, elapsed/remaining). Back to Now, Done, or six idle seconds bring the full controls back. VoiceOver actions "Hide Playback Controls" / "Show Playback Controls" (27.2 `TRANSCRIPT_ACCESSIBILITY_ACTION_*`) |
| Sync | Only cuts of episodes he had reviewed | New record kind `found` (`sync.found.v1`): ads found and not reviewed on the 150 most recently processed episodes — times, kind, the length of the copy and the finder version. Applied only to an episode the receiving device hasn't searched or corrected, from the same finder version, and whose measured copy (if any) is within 2 s. Marked `origin = "synced"`; the device's own search replaces them; not sent back. When a downloaded file turns out a different length (host stitches ads per download) the player drops them (`dropSyncedCutsThatDontFit`) and records it in the playback trace; a stream of a different length was already guarded (`streamCutsDiffer`). |
