Pass 48's code (8cdc0a8) and docs (121311e) went up in one push (`2159257..121311e`). A first empty trigger commit (41557dc) quoted the marker in its body and was skipped too. 446c03f started [run 40653164907](https://github.com/Throckmorton69420/podskipper/actions/runs/40653164907): **success**, and the "latest" release now targets 446c03f (07:55 UTC) — Pass 48's code. ## 2. Search results as Apple's (reference → source → sim)

Apple 27.2 RC strings: `SEARCH_RESULTS_TOP_RESULTS` "Top Results", `SEARCH_RESULTS_SHOWS`, `SEARCH_RESULTS_EPISODES`, `SEE_ALL`, `RECENTLY_SEARCHED_HEADER_TITLE` "Recently Searched", `RECENTLY_SEARCHED_CLEAR_ALL` "Clear", `NO_SEARCH_RESULTS_CONTENT_UNAVAILABLE_VIEW_TITLE/MESSAGE` "No Results" / "We couldn’t find anything for “%@”. Try something else.", `SEARCH_SHOW_SUBTITLE` "Show".

| Before | Now |
|---|---|
| A Shows shelf, then all 25 episodes in one list | **Top Results** first: up to four rows, shows whose titles answer the words (whole title > starts with > holds every word; case, accents, punctuation ignored), then such episodes, each labelled "Show · author" / "Episode · show". Then **Shows** (See All → unnumbered list) and **Episodes** (six, without the ones above; See All → all) |
| Recent searches remembered only on the keyboard's Search key, so the list was usually empty; shown in the accent colour with no heading | Opening any result remembers the search; "Recently Searched" heading with **Clear**; rows in plain text |
| The system's "No Results for …" / "Check the spelling…" | Apple's "No Results" / "We couldn’t find anything for “…”. Try something else." |

`SearchTopResults.pick` is a pure function (unit tests in `Tests/Pass49Tests.swift`). The Library source is unchanged.
