# PodSkipper — Product Specification & Decisions

Authoritative product intent, reconciled 2 October 2026. User decisions govern; this document is not a completion report. The [Request Catalog](claude/REQUEST-CATALOG.md) defines each acceptance item and evidence status. The [Implementation Plan](IMPLEMENTATION-PLAN.md) orders work; [Handoff](claude/HANDOFF.md) records exact delivered and unfinished state. Dated evidence cannot override a later user correction.

## Product and operating constraints

Build a polished iPhone/iPad podcast app with Apple Podcasts visual and functional parity, richer listening controls, reliable on-device ad/fluff detection, streaming video, and safe import, backup and publishing. The target reference is **Apple Podcasts iOS 27.2 beta 2**; the deployment target is **iOS 27**, not older 26.6/27.0 assumptions. The user tests on an iPhone 16 Pro, signs/installs unsigned IPAs with Feather and supplies phone feedback. Preserve the installed app, data and actual signing identity. Do not assume debug/container/direct-install access or add unrelated entitlements. (U15, C01–C02, G08)

Public RSS/host/Apple metadata and media may be used where legitimately available. Private/unavailable editorial/media content and unsupported signed capabilities require precise limitations. Existing code, successful compilation, simulator evidence and phone acceptance are different evidence levels. A failed phone check overrides an older pass label. Do not call the product complete while functionality or phone gates remain open. (L01, L12, V02–V04, C01, G01–G03)

## Design and model experience

Use shared native typography, proportional app sizing, accessible touch targets, Liquid Glass, stable scroll edges and restrained art/motion throughout; preserve system accessibility settings. Inspect actual screens, both orientations, sheet detents and large text. Keep Speed & Audio compact enough for useful EQ/speech-control space, preserve glass when expanded, and give Simple/Detailed charts equal geometry with readable frequency regions and ±15 dB intensity. Activity actions have equal dimensions and full labels. (U01–U18)

Keep four distinct engines: **Apple Intelligence, PodSkipper Reader, Apple Core AI, and open models through MLX**. Apple Intelligence remains default until another engine wins on real episode quality and practical phone cost. Reader retention/training is conditional on evidence, not an assistant's assumption that its small custom model is adequate. (M01, M16, D05–D07)

AI Settings uses the same order/explanations for every engine and shows the selected downloaded model and readiness. Both model libraries open their actual list directly, with consistent typography, download/enable/delete/cellular controls and result explanations. Apple Intelligence and Reader have descriptions, never fake downloads. Browse/download available compatible candidates; only downloaded, enabled, usable models may be selected for inference. Arbitrary estimated-memory refusal is not an acceptable substitute for measured supported runtime behavior. (M05–M08, M15, M18)

One shared **Compare models** destination is reachable from Settings and either library. Latest phone feedback requires **four visible engine rows**, with Basic/Hard controls beside each row, plain engine explanations, selected Core AI/MLX names and clear queued/running/error/stopped identity. Core AI/MLX rows have default-collapsed model lists with download/selection. Retain exact model/sample/policy/run histories when leaving the screen; failed/incomplete/cancelled tests never earn a success score. Do not implement an unapproved single-engine replacement for these rows. (U02–U03, M02–M04, M09–M14, M19; F301)

## Durable processing and performance

The library is opened once, by one owner, with the full schema; nothing opens it with a smaller schema, and a failed open never deletes, resets or replaces it but reports the real error and offers recovery (P23, Pass 33). One persisted per-episode job owns every queue, Activity/banner, player, preparation, notification and publishing projection. Preserve order across shows and relaunch; distinguish paused, explicitly stopped, interrupted, failed and completed. User stops stay stopped until explicit retry. Expose real stages/timings/progress, queue totals, finished results, meaningful failure reasons and exact-job notification routes. Stop cancels actual work; Restart/resume reuses versioned transcripts/answers and rejects late cancelled writes. (P01–P05, P08, P11–P20)

One heavy-work coordinator gives explicit user work priority and prevents competing transcription/inference/benchmarks/maintenance/preparation. Background behavior must honestly handle OS/resource/network waits, checkpoint and resume; bounded failed local attempts notify/offer Reader rather than silently changing the engine unless a measured hybrid preserves accuracy; a failed or crashed attempt never replaces a valid earlier result, every attempt keeps its engine/model/outcome provenance, and the global model choice changes only by the user's action (or by auto-selecting a model the user just downloaded). Do not invent progress or promise immunity from system expiration. Measure heat, memory, battery, launch and full-library scrolling on battery/charger with and without playback. Processing must never activate artificial silent audio or steal Bose multipoint audio. Completed transcripts are reused; explicit charging work may add word timing to old transcripts. (P06–P10, P16–P17, M17)

**Two standing decisions, clarified in Pass 32 (P21, P22).** (1) *"Nothing heavy starts in the background on its own"* governs PodSkipper's behaviour on the phone, not how Claude works on the Mac. It forbids the app from **starting new** heavy work (transcription, model reading, benchmarks, maintenance) that the user did not ask for while it is in the background; it does not forbid **resuming or continuing** work the user explicitly requested (a queued Find Ads, a Compare Models test, a download), which should carry on and resume honestly after interruption. (2) *"Finished transcripts are never redone"* means the words and timings are never transcribed again; the saved transcript may be re-windowed, re-chunked, re-formatted or re-prompted for a different model or policy, and explicit charging work may add word timing, without re-transcribing audio.

## Detection and correction policy

Classify with surrounding dialogue and transitions, not isolated sponsor/Patreon/promote/goodbye words. Distinguish paid/dynamic/host ads; self, guest, tour, Patreon, merch and network plugs; editorial/content transitions and recurring material; intros/outros/themes/credits/trailers/previews/bonus-content promotion; normal conversation and other non-ad material. **Cut paid ads and all plugs; keep comedic reads by default unless confidently plain reads.** 2 Bears' Mountain Dew is an ad; ordinary brand discussion or criticism is not an ad. Classification and episode → show → global skip preferences remain separate. (D03, D08–D11, D16, D19)

Preserve the working architecture while improving it: validated host ad-free alignment/fingerprints, cached word-timed transcripts, efficient candidates, contextual judgment, independent boundary refinement, confidence/evidence/uncertainty and review. Reject mismatched/shortened/unverifiable positives; retain negatives. Original predictions, edited/pending-lock corrections, added/rejected and final locked decisions stay distinct across reruns. Boundary/class edits, deletions, additions and thumbs are feedback with a measured future per-show effect. (D01–D04, D09–D13, D17–D18)

Use real episodes from the user's shows and held-out labels. Preserve MSSP 633/LoS and other reported failure regions for media verification; do not hard-code approximate unverified timestamps as truth. Targets are **≤10 seconds ads heard and ≤5 seconds program wrongly cut per hour**, with no catastrophic cuts or material regressions; these are goals, not achieved performance. Compatibility and speed are not detector quality. Mac Reader training is deferred until reliable corrections, diverse held-out shows and deployment regression gates exist. Pass 34: the offline evaluation set (`Tools/DetectionLab/evalset.py`) keeps his decisions, Claude-labelled fixtures and SponsorBlock crowd segments (reopened 9 Oct for offline evaluation only) as separate tiers, scores per show with a fixed dev/held-out split, and never feeds skipping decisions. (D05–D07, D14–D15, D17, M13–M14)

## Library, discovery and playback

Finish top-level pages **and all child destinations**: New, Search/categories/shelves/See All, results and previews, shows, episodes, people, Library, Up Next and Stations. Use truthful cached loading/offline/error/unknown-shelf states, current public editorial data, host/guest/transcript search and real related metadata. Persist sort/filter/season/year settings; retain full available publisher/catalogue history with honest indexing progress. Counts reflect newly released unheard followed episodes, not every historical unplayed episode. Batch actions follow visible/explicit selection; show metadata, HTML notes, artwork, dates/year, explicit/bonus/trailer/video labels and shared menus consistently. Stations support grouping/manual order; auto-download latest N/time windows/filters and remove-played apply only to rule-owned downloads. Catalogue save/identity failures must not erase pending listening edits or fake completion. (L01–L22, U10–U14)

Play/autoplay an unprocessed episode through the exact episode's five-second stream countdown: Play now starts, dismissal cancels, Process first queues. Stream without requiring full download/processing. Restore episode/position after crash/relaunch. Prepare chosen N follows explicit queue then show order; autoplay respects newest/oldest and enable setting; manually queued played episodes stay available; skip-forward at end advances. Find Ads remains available before processing; relevant skip toggles appear after. (A01, A05–A09)

Timeline spans show class/duration even for short cuts. Tap-inspection and intentional precision scrub are distinct; magnification preserves coordinates, paused seeks are exact, and ghost-origin/transcript interactions can return to the listening position. Bookmarks have equal icon size, visible count, tap-add/label and hold-list; mini-player artwork/date/title/progress remain readable. Review has independent playhead/trim handles, timestamps, zoom, step/preview controls, skip bypass, synchronized transcript, undo and original/corrected/locked states. Clips/Share from Here preserve exact episode/time. Calls, AirPods/Bluetooth/AirPlay, interruptions, Lock Screen and Live Activity reflect actual playback, not a stale icon. Title scrolling is required while active; avoid unnecessary always-on motion when the screen is asleep. (A02–A03, A10–A20, A24–A26)

One resolved sound plan drives audible DSP and charts: presets plus repairs, per-show inherited/custom settings (Pass 33: the app default, each show's own fields falling back to it, "This Show" in Speed and Audio saving a complete copy, "Use My Default" to revert, and Reset restoring a fresh install's values with explicit choice and Undo for shows' own settings; Pass 34: a fresh install and Reset are neutral — 1×, Smart Speed, Volume Normalization, Even Out Volume, Equalizer (flat), every sound fix and Mono off — and an update never changes what an existing install hears; Mono stays one switch because it describes how he listens, not the show), Smart Speed, mono, normalization, sibilance/de-essing, clarity and bass/mud/harshness controls with understandable explanations. Consolidate duplicate controls without losing saved settings. The same desired speech/speed/EQ options apply to video, with actual audible device evidence or a specific supported-path limitation. (A04, A21–A23)

## Video, data and publishing

Resolve same-episode video from RSS alternate-enclosure HLS/native video, legitimate public host/Apple links, then reliable YouTube fallback. Do not make reverse engineering Apple private HLS delivery the primary solution. Avoid separate duplicate episode identity. Full-width video, cover/video taps, fullscreen/swipe-dismiss/PiP, always-start-in-video and switching around cuts share one episode timebase. Stream video without persistent retention; protect active media, clean temporary extraction safely and retain failed-deletion references. Verify changing nonblack decoded frames and actual phone sync/DSP/startup, not just a visible container. Stavvy #198/#199 need honest source diagnosis. (V01–V08, A23)

Full versioned backup/export covers listening/history/resume/settings/corrections/transcripts/processing/checkpoints/downloads and pertinent diagnostics; OPML is subscription interchange. Restore through staged journal/rollback on disposable data, including old/corrupt/iCloud placeholder/interrupted/disk-full cases and reinstall/new identity. Manage newest N/individual/orphaned app-owned backups and category-scoped cleanup; protect external files and playing media, give honest totals/confirmation. OPML must actually be selectable. Apple history import uses genuine played records and exact show/GUID identity, reports unmatched/incomplete catalogue and never conflates CumTown/MYCTP/Adam Friedland. (B01–B12)

Publishing reuses completed detection/corrections, writes corrected audio and maintains one feed URL per show. Selected batches queue/reorder/cancel/retry and auto-publish idempotently, including network loss/relaunch. Steps, ready/published/update states and feed copy/open in Apple Podcasts are truthful. A unified Library/publishing workflow is permitted if it preserves all functionality; the Gemini mockup is advisory. Exercise actual signed widgets/CarPlay/iCloud/Live Activity/Intents/Action-button support; source presence is not capability acceptance. (F01–F07, C01–C05)

## Settled scope and execution decisions

Declined unless explicitly reopened: Siri/Private Cloud Compute; artwork swipe-to-scrub; AdGuard/tweaked-IPA YouTube ad blocking; a reduced locked-screen quick check replacing contextual detection; gray Contacts-style Settings index. Earlier download-only playback, mandatory embedded Bonsai, direct-main delivery and iPhone-mirroring/access assumptions are superseded. (W01–W10)

Use local Xcode/simulator for builds/tests and actual UI inspection; GitHub compiles/packages the unsigned IPA. Preserve rollback and complete validated batches, additive copied-data migrations and atomic local checkpoints with consolidated pushes. Reuse caches and focused evidence; no caffeinate, unnecessary polling or tiny repeated phone-test requests. Use relevant Apple skills/official API evidence. Update the catalog and handoff after each batch with exact revision, implementation evidence, unresolved failures and next action. Historical cloud delegation, usage balances, model rankings and assistant “done” labels do not create new permissions or product facts. (G01–G12)
